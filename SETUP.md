# Первая настройка системы каруселей

Инструкция для Claude. Выполнять по порядку, в папке системы (где лежит `make.py`).

## Как вести себя с пользователем

- Пользователь, скорее всего, первый раз работает с нейросетью и терминалом. Перед каждым этапом одной фразой простыми словами: что сейчас будет и зачем. Без терминов: не «venv», а «отдельная папка с программами для системы».
- Всё, что можно сделать самому, делать самому. От пользователя нужно только: нажимать «Yes», ответить на анкету, один раз войти в Google, иногда ввести пароль от компьютера.
- Перед командой, которая попросит пароль от компьютера, предупредить: «сейчас Терминал попросит пароль от Mac — вводи, символы не видны, это нормально, потом Enter». На Windows вместо пароля всплывает окно «Разрешить изменения?» – предупредить, что нужно нажать «Да».
- Вопросы анкеты — по одному-два за раз, с примером ответа. Можно отвечать голосом через диктовку, коротко, «не знаю» — тоже ответ.
- Ничего не придумывать за пользователя: ни фактов, ни цифр, ни цветов, ни ника. Если ответа нет — оставить пусто или предложить варианты на выбор.
- Ошибка при установке — не пугать пользователя логом. Самому разобраться и починить, ему сказать одной строкой, что случилось.
- Ход установки отмечать в `config.json` → `setup_step` (1–5), чтобы после перезапуска продолжить с того же места.

## Шаг 1. Установка программ

1. Определить систему (`uname` или PowerShell). У каждого пункта ниже команда для Mac и отдельно для Windows. Python в папке системы: Mac – `.venv/bin/python`, Windows – `.venv\Scripts\python`; дальше в тексте `.venv/bin/python`, на Windows подставлять второй путь.
2. **Google Chrome.** Проверить `/Applications/Google Chrome.app` (Windows: `C:\Program Files\Google\Chrome\Application\chrome.exe`). Нет — скачать и поставить:
   `curl -L -o /tmp/chrome.dmg https://dl.google.com/chrome/mac/universal/stable/GGRO/googlechrome.dmg && hdiutil attach -nobrowse -quiet /tmp/chrome.dmg && cp -R "/Volumes/Google Chrome/Google Chrome.app" /Applications/ && hdiutil detach -quiet "/Volumes/Google Chrome"`
   (Windows: `winget install -e --id Google.Chrome`).
3. **uv** — менеджер Python, ставит всё в домашнюю папку без пароля: `command -v uv || curl -LsSf https://astral.sh/uv/install.sh | sh`. После установки вызывать его по полному пути `~/.local/bin/uv`, если `uv` не находится.
   (Windows: `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`).
4. **Python и библиотеки** в папке системы:
   `uv venv --python 3.12 .venv && uv pip install --python .venv -r requirements.txt`
5. Проверка: `.venv/bin/python make.py check`. Если Chrome не запускается для рендера — `.venv/bin/python -m patchright install chromium`.
6. **Пробная вёрстка:** `.venv/bin/python make.py render examples/demo`. Открыть `examples/demo/contact_sheet.png` (`open` на Mac, `start` на Windows), посмотреть самому, что шрифты и картинки на месте. Пользователю сказать: «Программы стоят, система верстает. Теперь настроим её под тебя».

## Шаг 2. Анкета

Сказать: «Задам вопросы про твой блог — по ним система будет писать в твоём стиле. Отвечай как есть, коротко».

1. **Профиль.** Ник в Instagram. Имя в шапке профиля, как оно написано. 1–3 строки описания профиля. Сколько сейчас публикаций, подписчиков, подписок (для карточки профиля на последнем слайде; можно примерно, потом обновим).
2. **Блог.** О чём блог и кто ты: 2–3 предложения. Пример: «Я косметолог из Казани, рассказываю, как ухаживать за кожей без дорогих процедур».
3. **Аудитория.** Кто читает: возраст, чем занимаются. Что у них болит, чего хотят, что уже пробовали.
4. **Что продаёшь и куда ведёшь.** Услуги, продукты, цены, если хочешь их упоминать. Куда зовёшь людей: директ, Telegram, сайт, бесплатный урок или вебинар. Есть ли подарок за кодовое слово («напиши СЛОВО — пришлю чек-лист»): какой подарок и какое слово.
5. **Факты о тебе.** Опыт, результаты, кейсы клиентов — только реальные, с цифрами, если есть. Объяснить: «В карусели попадут только эти цифры, я ничего не буду придумывать».
6. **Как ты говоришь.** На «ты» или на «вы». Попросить прислать 2–3 своих поста или подписи (просто вставить текст). По ним самому описать стиль: длина фраз, словечки, юмор, эмодзи. Показать описание пользователю и спросить, похоже ли.
7. **Запреты.** Что нельзя говорить и обещать: темы, слова, конкуренты.
8. **Темы.** 3–5 тем или рубрик, о которых хочется делать карусели.
9. **Аватарка.** Попросить перетащить фото в окно Терминала или PowerShell (так вставится путь к файлу) или написать «пока нет». Скопировать в `templates/photos/avatar.jpg` (если это не jpg — конвертировать через Pillow).
10. **Стиль.** Спросить фирменные цвета (код вида #FF7A1F или словами: «тёмно-зелёный»). Нет фирменных — предложить 3 акцентных цвета на выбор под нишу. Потом сверстать пример в двух темах с его акцентом и его ником (сначала записать ник в `config.json`):
    `make.py render examples/demo --theme dark --accent <цвет>` → скопировать contact_sheet как `output/_style/dark.png`;
    `make.py render examples/demo --theme light --accent <цвет>` → `output/_style/light.png`.
    Открыть обе картинки и спросить, какая ближе. Если пользователь присылает ссылки на любимые карусели или скрины — посмотреть и учесть при выборе цвета и темы. Тёмная тема: можно поменять фон (`bg`).

После анкеты:
- Заполнить `brand.md` по разделам шаблона словами пользователя. Не выдумывать, пустое оставить пустым.
- Заполнить `config.json`: `handle`, `theme`, `accent`, `bg`, `profile` (`name`, `posts`, `followers`, `following`, `bio` — список строк).
- Показать пользователю коротко, что записано, и спросить, всё ли верно.

## Шаг 3. Пиксельные картинки через Gemini

Сказать: «В системе уже есть 100+ пиксельных картинок для слайдов. Можно подключить Gemini, чтобы делать свои под твою тему. Нужен аккаунт Google. Подключаем?» Если нет — пропустить шаг.

1. `make.py gemini` — откроется отдельное окно Chrome с Gemini. Попросить пользователя войти в свой Google-аккаунт в этом окне и написать «готово». Пароль вводит только пользователь.
2. Придумать 5 сцен под нишу пользователя (предметы и образы из его тем: что болит у аудитории, что получает после). Добавить в `templates/pixel/library.json`: id латиницей через дефис, `ru` — что изображено и когда ставить, `en` — описание предмета на английском для генерации (один предмет, без текста).
3. `make.py pixels <id1> <id2> …` — генерация идёт по одной картинке, это небыстро. Показать результат.
4. Если Gemini пишет про лимит — остановиться, остальное сделать в другой день той же командой.

## Шаг 4. Первая карусель

1. Предложить 3 темы для первой карусели из ответов анкеты. Пользователь выбирает.
2. Сделать карусель строго по скиллу `.claude/skills/carousel/SKILL.md` (прочитать его и выполнить все шаги, включая показ хуков и ожидание выбора).
3. Показать результат и путь к папке. Объяснить, как перенести PNG на телефон: AirDrop (Mac) или отправить себе в Telegram «Избранное» как файлы (Mac и Windows).

## Шаг 5. Завершение

1. В `config.json` поставить `"setup_done": true`.
2. Дать пользователю шпаргалку (коротко):
   - Каждый раз: Mac – открыть Терминал → `cd ~/Desktop/carousels && claude`; Windows – открыть PowerShell → `cd ~/Desktop/carousels; claude`.
   - Пишешь обычным текстом: «сделай карусель про …», «вот мой пост, упакуй в карусель: …», «карусель-список: 5 ошибок …», «слайд 3 слишком плотный», «смени хук на второй вариант», «сделай светлую версию».
   - Готовое: `output/<дата>_<тема>/` — `slide_01.png` … и `caption.txt`.
   - Новая картинка-сцена: «добавь пиксельную картинку: <что нарисовать>».
   - Поменять что-то в стиле или о себе: «добавь в brand.md, что …», «смени акцентный цвет на …».
   - Если повторяешь одну и ту же правку — скажи «запомни это», и Claude допишет правило.
3. Попросить перезапустить Claude один раз (`/exit`, потом снова `claude` в этой папке), чтобы подключились команды системы.
