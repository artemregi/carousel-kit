# Карусель: алгоритм

Карусель — одна мысль автора, разложенная на 6–10 экранов. Материал: тема, текст поста, сценарий рилса, расшифровка эфира или чужой залетевший пост (тогда берётся механизм, а не текст). Кто автор, для кого пишет, факты о нём и запреты — только из `brand.md`. Вёрстку делает код (`make.py render`), нейросеть пишет только `slides.json`.

## 1. Размеры Instagram

- Формат 4:5, все слайды одного размера. Вёрстка в сетке 1080×1350, PNG выгружается в 1440×1800: это максимум, который Instagram хранит для 4:5, на плотных экранах заметно чётче.
- В сетке профиля пост обрезается до 3:4: с боков уходит по ~34 px. Текст и лица держать в центральных 1012 px → поля не меньше 56 px.
- Сверху и снизу 30–40 px под плашку ника и «листай дальше →». Основной текст — в зоне от 90 до 1270 px по высоте.
- Длина 6–10 слайдов. Максимум Instagram — 20, но у сильных авторов медиана 7–8.
- Мельче 24 px на слайде ничего нет, кроме служебных плашек. С телефона (ширина 375 px) 24 px превращаются в 8 pt — это предел.

## 2. Вовлечение: почему листают до конца, сохраняют и пересылают

Карусель — не набор карточек, а один рассказ, разрезанный на экраны. Каждый слайд отвечает на вопрос, возникший на предыдущем, и создаёт новый.

1. **Одна мысль.** Сначала формулируется одним предложением (`thought`). Не формулируется — карусели нет.
2. **Архитектура по материалу** (выбрать одну, поле `architecture`):
   - **список** — «N ошибок / мест / способов», один пункт на слайд → сохранения;
   - **проблема → решение** — хук, где болит, поворот, как работает, пример, вывод → доверие;
   - **мнение** — провокация, «все думают, что…», почему нет, моя позиция жёстко → комментарии;
   - **история** — момент напряжения из середины, путь, поворот, результат, вывод → личный бренд;
   - **кейс** — было → стало цифрой, что мешало, шаги, доказательство, вывод → только с реальными цифрами из `brand.md` или со слов автора.
3. **Хук — 3–5 вариантов из разных паттернов** (поле `hooks`), на обложку идёт сильнейший. Паттерны: против общепринятого, недосказанность, ошибка, обещание «X без Y», цифра, было → стало, история с середины, сильный вопрос, манифест, «я сделал X — вот что вышло», общий враг, «N способов». Заголовок обложки до 8 слов, первое слово — уже смысл, тема понятна без подписи. Нельзя: «в этом посте расскажу», вопрос с ответом «нет», две мысли на обложке.
4. **Тест свайпа.** После каждого слайда должен остаться вопрос «а дальше?». Нет вопроса — слайд лишний или слабый. Если слайды можно поменять местами без потери смысла — структура слабая.
5. **Открытая петля.** Обложка обещает ответ, который выдаётся не раньше 60% карусели. Ответ обязателен — без него доверие падает.
6. **Поворот.** Один слайд меняет ожидание: «на самом деле всё наоборот». Обычно 3–5-й.
7. **Ритм плотности.** После плотного слайда — «воздушный»: одна крупная мысль, сцена. Подряд не больше двух плотных. Минимум два лёгких (обложка + поворот).
8. **Сохраняемость.** Хотя бы один слайд, к которому хочется вернуться: шаги, чек-лист, итог списком.
9. **Один призыв с причиной.** Обучение → «сохрани, чтобы [зачем вернуться]»; мнение → «согласен? напиши [конкретный вопрос]»; история → «подпишись — [что будет дальше]». Не два действия сразу. Кодовое слово («напиши СЛОВО — пришлю …») — только если в `brand.md` есть лид-магнит и слово.

## 2.1. Каркас слайдов

1. **Обложка.** Если архитектура «список» — цифра первым словом («5 мест, где…»), она выносится крупно. Под заголовком строка, что внутри.
2. **Внутренние слайды: 4–7.** Шаблон: заголовок 2–6 слов (суть, не «Во-первых») → пояснение 1–2 строки, до 25 слов → вывод одной жирной строкой (необязательно) → визуал по смыслу (§3).
3. **Итог** (для списка и проблемы → решения): все пункты одной строкой каждый.
4. **Последний слайд** — призыв (п. 9) и карточка профиля.

Не пересказывать материал подряд, а разложить мысль по архитектуре. Из чужого залетевшего поста брать механизм, а не текст: свои слова, своя ниша.

## 3. Визуал слайда — по сигналу в тексте

| Сигнал в пункте | Визуал | Что внутри |
|---|---|---|
| Переписка, директ, заявка, ответ клиенту | `chat` | 2–4 сообщения: «them» — подписчик, «me» — автор |
| Шаги, порядок действий | `steps` | 3–5 коротких шагов |
| Одна проверенная цифра | `stat` | число + подпись |
| «Было → стало», вручную vs по-новому | `compare` | две колонки по 2–3 строки |
| Конкретный сайт, сервис, приложение | `shot` | **обязательно** настоящий скрин (`src` — путь к PNG, `cap` — адрес сайта). Снять: `make.py shot <url> output/<папка>/shots/<имя>.png` |
| Инструмент или решение для задачи | `arrow` | стрелка вниз → крупное название + иконка (только из `make.py icons`) |
| Насколько это просто/сложно, порог входа | `gauge` | пиксельный спидометр: легко / средне / сложно — уровень обязан совпадать с заголовком |
| Образ, эмоция, предмет: пустой кошелёк, выгорание, нет идей, опоздал | `scene` | пиксельная картинка — только id из `make.py scenes` |
| Ничего из этого | без визуала | заголовок крупнее, текст по центру |

**Наклейка-счётчик** у переписки (`badge`): красная плашка «+399», «47 непрочитанных» — только если цифра реальная или явно условная.

Пиксельный слой: 2–3 слайда на карусель со `scene` или `gauge`, не больше — иначе карусель превращается в игру. Сцена ставится, только если она по смыслу совпадает с пунктом, а не ради картинки. Нужной сцены нет — добавить её в `templates/pixel/library.json` (поля `ru` и `en`) и сгенерировать `make.py pixels <id>`.

**Наглядность обязательна.** Если карусель про инструменты или сервисы, на каждом слайде с ним стоит `shot`. На странице снимать блок с примером результата, а не только шапку сайта (`make.py shot <url> <файл> "<css-селектор>"`). Только реальные страницы, интерфейс не подделывать. Лучше всего — собственные скрины автора: предлагать прислать.

Слайд без визуала — не больше одного на карусель: он выглядит пустым. Не больше 2 одинаковых визуалов подряд. Переписка — макет, не скриншот: в ней нет имён реальных людей и выдуманных цифр.

## 4. Рукописные пометки

Поле `note` — короткая реплика ручкой на полях (цвет пера темы) со стрелкой, как будто автор подписал распечатку. Заполняет пустое место и даёт живой голос.
- 2–4 слова, разговорно: «знакомо?», «вот тут теряешь», «сохрани себе», «это главное», «жми».
- На 3–5 слайдах из всей карусели, не подряд на всех. Обложка и последний слайд — да, если к месту.
- Не повторяет заголовок и не несёт новых фактов.

## 5. Текст

- Голос автора из `brand.md`: «ты» или «вы», длина фраз, его словечки. Короткие фразы. Слово-акцент в заголовке — одно на слайд, отмечается `**так**`.
- Каждый слайд читается отдельно: человек может пролистать на середину.
- Цифры, кейсы, имена — только из `brand.md` или со слов автора в этом разговоре. Нет данных — спросить автора или писать без цифры. Выдумывать нельзя.
- Нельзя: запреты из `brand.md`, обещать заработок, ИИ-штампы («в современном мире», «давайте разберёмся», «это не просто X, а Y», «ключ к успеху», «надеюсь, было полезно», «погрузимся»), риторические вопросы подряд.
- Подпись к посту (`caption`) дублирует пункты списком, чтобы карусель находилась поиском.

## 6. Оформление (делает код, не нейросеть)

Тема — `config.json` → `theme`. `dark`: тёмный фон (`bg`), заголовки капсом Oswald, слово-акцент цветом `accent`, пояснения в белых скруглённых карточках, рукописные пометки и стрелки цветом акцента (Caveat), пиксельные сцены и спидометр на белых карточках, последний шаг и правая колонка сравнения — цветом акцента. `light`: белый фон, Inter, красная ручка.

Сверху по центру плашка ника, снизу «листай дальше →» на всех слайдах, кроме последнего. Никаких теней, градиентов и свечения. Переписка — макет директа. Сравнение — ✕ слева, ✓ справа. Пиксельные сцены на слайде увеличиваются в целое число раз без сглаживания, подписи к ним — Press Start 2P. Последний слайд — карточка профиля из `config.json` → `profile` с аватаркой `templates/photos/avatar.jpg`.

## 7. Проверка перед показом автору

- [ ] Обложка: до 8 слов, тема понятна без подписи.
- [ ] Тест свайпа пройден на каждом слайде, петля закрыта после 60%.
- [ ] Есть поворот и хотя бы один «сохраняемый» слайд.
- [ ] Нет выдуманных цифр, кейсов, имён. Все `shot` — настоящие скрины.
- [ ] Не больше одного слайда без визуала, не больше 2 одинаковых визуалов подряд.
- [ ] `make.py render` без предупреждений «не влез» / «за краем». Если шрифт уменьшен ниже 85% — сократить текст, а не мириться.
- [ ] Contact sheet просмотрен глазами: ничего не пустое, не налезает, акцент одно слово на слайд.
- [ ] Один призыв на последнем слайде.
